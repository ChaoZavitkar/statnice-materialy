Konceptuální návrh

Tři úrovně návrhu databáze:
  1. Konceptuální — co existuje v reálném světě: entity, atributy, vztahy (nezávislé na DB systému)
  2. Logický — jak to uložíme v relačním modelu: tabulky, klíče, normalizace, E-R diagram
  3. Fyzický — SQL příkazy v konkrétním DBMS: CREATE TABLE, datové typy, indexy

Odvozené atributy — příklad z PDF zadání:
Zadání uvádí atribut počet studentů u entity předmět. Tento atribut je odvozený — jeho hodnota plyne z počtu záznamů ve vazební tabulce a lze ji kdykoli získat přes SELECT COUNT(*). Ukládání odvozeného atributu by způsobilo redundanci a anomálie při aktualizaci, proto ho při návrhu vynecháme.

Postup při návrhu z PDF zadání:
  1. Identifikovat entity ze slovního popisu (podstatná jména)
  2. Identifikovat atributy každé entity
  3. Identifikovat vztahy (slovesa: studuje, pracuje, vlastní…)
  4. Určit kardinality (1:1, 1:N, M:N)
  5. M:N vztahy rozložit na vazební tabulku
  6. Každá tabulka musí mít primární klíč

Normalizace (1NF → 2NF → 3NF)

Cíl normalizace: Eliminovat redundanci dat a anomálie při vkládání, úpravě a mazání.

1. normální forma (1NF)

Požadavek: Každá buňka obsahuje atomickou hodnotu (ne seznam, ne více hodnot).

❌ Porušení:
student_idjmenopredmety
1AnnaMatematika, Fyzika
✅ Oprava: Každý předmět na samostatný řádek (nebo vazební tabulka)

2. normální forma (2NF)

Požadavek: Musí být v 1NF + každý neklíčový atribut závisí na celém primárním klíči (ne jen jeho části).
Relevantní jen při složeném PK.

❌ Porušení (tabulka zapis se složeným PK student_id + predmet_id):
student_idpredmet_idjmeno_studentanazev_predmetu
110AnnaMatematika
jmeno_studenta závisí jen na student_id — porušení!
✅ Oprava: Přesunout jmeno_studenta do tabulky student, nazev_predmetu do tabulky predmet

3. normální forma (3NF)

Požadavek: Musí být v 2NF + žádný neklíčový atribut tranzitivně nezávisí na PK (atributy závisí přímo na PK, ne na jiném neklíčovém atributu).

❌ Porušení:
student_id (PK)program_idnazev_programudelka_programu
12Informatika Bc.3
nazev_programu závisí na program_id, ne na student_id — tranzitivní závislost!
✅ Oprava: Vytvořit samostatnou tabulku studijni_program(program_id, nazev, delka)

Omezení (constraints)

CREATE TABLE studijni_program (
    program_id  SERIAL          PRIMARY KEY,        -- auto-increment PK
    nazev       VARCHAR(100)    NOT NULL UNIQUE,     -- povinné + unikátní
    titul       CHAR(2)         NOT NULL,            -- 'Bc', 'Ing', 'Mgr'
    delka_let   INTEGER         NOT NULL CHECK (delka_let BETWEEN 1 AND 6)
);

CREATE TABLE student (
    student_id      SERIAL          PRIMARY KEY,
    jmeno           VARCHAR(50)     NOT NULL,
    prijmeni        VARCHAR(50)     NOT NULL,
    datum_narozeni  DATE            NOT NULL,
    email           VARCHAR(100)    UNIQUE,          -- může být NULL, ale unikátní
    program_id      INTEGER         REFERENCES studijni_program(program_id)
                                    ON DELETE SET NULL   -- při smazání programu nastaví NULL
);

CREATE TABLE predmet (
    predmet_id  SERIAL          PRIMARY KEY,
    nazev       VARCHAR(100)    NOT NULL,
    rocnik      INTEGER         NOT NULL CHECK (rocnik BETWEEN 1 AND 4),
    semestr     CHAR(2)         NOT NULL CHECK (semestr IN ('ZS', 'LS'))
);

-- Vazební tabulka pro M:N vztah student — predmet
CREATE TABLE zapis (
    student_id  INTEGER     NOT NULL REFERENCES student(student_id) ON DELETE CASCADE,
    predmet_id  INTEGER     NOT NULL REFERENCES predmet(predmet_id) ON DELETE CASCADE,
    datum       DATE        DEFAULT CURRENT_DATE,
    PRIMARY KEY (student_id, predmet_id)    -- složený primární klíč
);
ON DELETE akce pro cizí klíče:
  • RESTRICT / NO ACTION — zakáže smazání rodiče, pokud existují děti (výchozí)
  • CASCADE — smaže i všechny závislé záznamy
  • SET NULL — nastaví FK na NULL
  • SET DEFAULT — nastaví FK na výchozí hodnotu

SELECT — dotazy

Pořadí klauzulí v SELECT: 
SELECT  [sloupce / agregace]       -- projekce: co zobrazit
FROM    [tabulka]                   -- odkud
[JOIN   [tabulka] ON [podmínka]]    -- spojení
WHERE   [podmínka]                  -- selekce: které řádky
GROUP BY [sloupce]                  -- seskupení
HAVING  [podmínka na skupiny]       -- filtr skupin (jako WHERE po GROUP BY)
ORDER BY [sloupce] [ASC|DESC]       -- řazení
LIMIT   [n]                         -- omezení počtu výsledků

Základní SELECT, WHERE, ORDER BY

-- Všechny sloupce
SELECT * FROM student;

-- Projekce — vybrané sloupce
SELECT jmeno, prijmeni, datum_narozeni FROM student;

-- Selekce — filtrace řádků (WHERE)
SELECT * FROM student WHERE program_id = 1;
SELECT * FROM predmet WHERE rocnik = 2 AND semestr = 'LS';
SELECT * FROM student WHERE email IS NOT NULL;
SELECT * FROM predmet WHERE nazev LIKE '%databáz%';   -- LIKE: % = libovolný text

-- Řazení (ORDER BY)
SELECT * FROM student ORDER BY prijmeni ASC;          -- vzestupně (výchozí)
SELECT * FROM studijni_program ORDER BY nazev DESC;   -- sestupně

JOIN — spojení tabulek

Typy JOIN:
TypVrátí
INNER JOINPouze řádky se shodou v obou tabulkách
LEFT JOINVše z levé tabulky + shody z pravé (NULL pokud neshoduje)
RIGHT JOINVše z pravé tabulky + shody z levé
FULL JOINVše z obou tabulek
 
-- 1. Vzorová úloha: Zobrazit všechny studenty a jména předmětů, které studují
SELECT s.jmeno, s.prijmeni, p.nazev AS predmet
FROM student s
INNER JOIN zapis z ON s.student_id = z.student_id
INNER JOIN predmet p ON z.predmet_id = p.predmet_id
ORDER BY s.prijmeni, p.nazev;

-- LEFT JOIN: studenti včetně těch bez zápisů
SELECT s.jmeno, s.prijmeni, p.nazev
FROM student s
LEFT JOIN zapis z ON s.student_id = z.student_id
LEFT JOIN predmet p ON z.predmet_id = p.predmet_id;

-- Spojení se studijním programem (1:N)
SELECT s.jmeno, s.prijmeni, sp.nazev AS program
FROM student s
INNER JOIN studijni_program sp ON s.program_id = sp.program_id;

GROUP BY — seskupení a agregace

-- Agregační funkce: COUNT, SUM, AVG, MIN, MAX

-- 2. Vzorová úloha: Studijní programy a počty studentů, seřazené dle názvu
SELECT sp.nazev AS program, COUNT(s.student_id) AS pocet_studentu
FROM studijni_program sp
LEFT JOIN student s ON sp.program_id = s.program_id
GROUP BY sp.nazev
ORDER BY sp.nazev ASC;

-- 3. Vzorová úloha: Předměty seskupené dle ročníku (agregace názvů)
SELECT rocnik,
       STRING_AGG(nazev, ', ' ORDER BY nazev) AS predmety
FROM predmet
GROUP BY rocnik
ORDER BY rocnik;

-- Filtrování skupin pomocí HAVING
SELECT program_id, COUNT(*) AS pocet
FROM student
GROUP BY program_id
HAVING COUNT(*) > 10;   -- pouze programy s více než 10 studenty

-- Příklady dalších agregací
SELECT
    semestr,
    COUNT(*)    AS pocet_predmetu,
    MIN(rocnik) AS nejnizsi_rocnik,
    MAX(rocnik) AS nejvyssi_rocnik
FROM predmet
GROUP BY semestr;

-- ═══════════════════════════════════════
-- 1. Vytvoření tabulek (fyzický návrh)
-- ═══════════════════════════════════════
CREATE TABLE studijni_program (
    program_id  SERIAL       PRIMARY KEY,
    nazev       VARCHAR(100) NOT NULL UNIQUE,
    titul       CHAR(3)      NOT NULL,
    delka_let   INTEGER      NOT NULL
);

CREATE TABLE student (
    student_id     SERIAL       PRIMARY KEY,
    jmeno          VARCHAR(50)  NOT NULL,
    prijmeni       VARCHAR(50)  NOT NULL,
    datum_narozeni DATE         NOT NULL,
    program_id     INTEGER      REFERENCES studijni_program(program_id)
);

CREATE TABLE predmet (
    predmet_id  SERIAL       PRIMARY KEY,
    nazev       VARCHAR(100) NOT NULL,
    rocnik      INTEGER      NOT NULL,
    semestr     CHAR(2)      NOT NULL
);

CREATE TABLE zapis (
    student_id  INTEGER  REFERENCES student(student_id) ON DELETE CASCADE,
    predmet_id  INTEGER  REFERENCES predmet(predmet_id) ON DELETE CASCADE,
    PRIMARY KEY (student_id, predmet_id)
);

Tipy pro zkoušku:
  • Při normalizaci vždy zkontrolovat: jsou všechna M:N rozložena do vazební tabulky?
  • Každá tabulka musí mít PRIMARY KEY
  • SERIAL = auto-increment; nemusíme zadávat hodnotu při INSERT
  • STRING_AGG(sloupec, ', ') agreguje textové hodnoty do jednoho řetězce
  • Pokud studijní program nemá studenty, LEFT JOIN ho stále zobrazí (COUNT = 0)
  • PostgreSQL: příkazy ukončovat středníkem ; v psql
  • Konzolový klient PostgreSQL se jmenuje psql (PDF chybně uvádí pgsql)
